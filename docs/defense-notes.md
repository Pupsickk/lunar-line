# Выступление и вопросы для защиты

## Текст выступления на 5–7 минут

**Слайд 1, около 30 секунд.** Я представляю «Лунную линию» — учебный сайт продажи индивидуальных раскладов Таро. Проект охватывает восемь этапов: анализ, HTML, оформление, дизайн-макет, сетки, интерактивность, адаптивность и итоговую сборку. Сайт использует HTML, CSS и JavaScript и запускается через Live Server.

**Слайд 2, около 40 секунд.** Главная задача интерфейса — помочь человеку сравнить форматы и пройти понятный сценарий оформления. Я описал три условные персоны. Они различаются опытом, устройством и целью визита. Поэтому цена, тема и объём сессии видны уже в каталоге. В проекте нет выдуманной статистики продаж или заявлений об опыте реального таролога.

**Слайд 3, около 45 секунд.** Карта сайта содержит 17 страниц. Есть главная, каталог, шесть отдельных раскладов, раздел о проекте, объяснение процесса, FAQ, примеры отзывов, контакты, корзина, оформление, конфиденциальность и условия. Глубина структуры не превышает трёх уровней. Внутренние страницы имеют хлебные крошки, а меню выделяет текущий раздел. Проект превышает минимальное требование итоговой работы в три страницы.

**Слайд 4, около 45 секунд.** Палитра состоит из светлого фона, тёмного текста и лилового акцента. Декоративное золото используется в иллюстрациях. Заголовки оформлены Georgia, основной текст Arial. Я подготовил четыре чёрно-белых прототипа и набор исходников для Figma: макеты, стили, компоненты и варианты кнопки. Перед защитой нужно завершить импорт, проверить макет и добавить ссылку на Figma. Это ограничение нельзя скрывать.

**Слайд 5, около 50 секунд.** Адаптивность построена по принципу Mobile First. На смартфоне содержимое идёт в колонку. От 768 px сетка услуг содержит две колонки, от 1100 px — три. Размер заголовка меняется через clamp. Мобильное меню управляется кнопкой и закрывается Escape. В пяти тестовых фреймах ширина документа совпала с доступной шириной. Это проверка в Chrome, а не заявление о тестировании физических телефонов.

**Слайд 6, около 60 секунд.** Flexbox использован для шапки, преимуществ и подвала. Grid — для услуг, отзывов и контактов. JavaScript отвечает за фильтры, сортировку, корзину, форму и меню. Корзина хранится в localStorage, но содержит только идентификаторы услуг и количества. Цена берётся из каталога кода и пересчитывается при изменении количества. Имя, email и вопрос не записываются в постоянное хранилище. Формы работают в демонстрационном режиме. Реальную оплату и серверную отправку проект не выполняет.

**Слайд 7 и демонстрация, около 90 секунд.** Открываю каталог, выбираю отношения и добавляю расклад. В корзине увеличиваю количество до двух: 1490 × 2 = 2980 рублей. Перехожу к оформлению и отправляю пустую форму, чтобы показать сообщения. Затем ввожу тестовое имя, test@example.com, отмечаю согласие и создаю демозаказ. После этого показываю мобильное меню и FAQ. Завершаю перечислением фактически проведённых проверок. W3C после исправлений, Lighthouse и другие браузеры нужно проверить отдельно, пока этих результатов нет.

## Короткие ответы на вопросы

- **Зачем семантические теги?** Они обозначают назначение областей страницы и помогают навигации, поисковым системам и вспомогательным технологиям.
- **Flexbox или Grid?** Flexbox удобен для ряда или колонки элементов; Grid задаёт сетку по двум осям.
- **Как работает clamp?** Ограничивает значение минимальным и максимальным пределами при гибком предпочтительном значении.
- **Что такое Mobile First?** Базовые стили для узкого экрана, расширения через min-width.
- **Почему валидация есть и в HTML, и в JS?** HTML задаёт ограничения, JavaScript управляет сообщениями, фокусом и дополнительными правилами. При настоящей отправке нужна также серверная проверка.
- **Безопасен ли localStorage для персональных данных?** Он доступен JS в этом origin. Здесь там хранятся только коды услуг и количества.
- **Что такое lazy loading?** Отложенная загрузка изображений вне первого экрана, чтобы уменьшить начальную нагрузку.
- **Почему нет онлайн-оплаты?** Это учебная реализация интерфейса. Для настоящих платежей нужны отдельная серверная интеграция и подтверждение результатов оплаты.
- **Приватный репозиторий доступен по одной ссылке?** Нет, друг должен иметь доступ как приглашённый пользователь. Приватность исходников и опубликованного сайта — разные настройки.
