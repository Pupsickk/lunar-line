# ЛР2.3 — WebSocket-чат поддержки

```text
npm ci
npm start
```

Открыть http://127.0.0.1:8080 в двух вкладках, войти под двумя именами. HTTP и WebSocket работают на одном порту 8080. Открывать HTML через file:// не нужно.

Проверки: сообщение появляется в обеих вкладках; Enter отправляет; индикатор набора исчезает через 2 секунды; выход участника виден в другой вкладке; новый участник получает 50 последних сообщений. Имена могут совпадать: свои сообщения определяются по серверному UUID, а не по имени. Имя из входящего message игнорируется, сервер берёт его из подключения.

Дополнительно реализованы список онлайн, история в памяти, ping/pong, повторное подключение кнопкой, ограничение частоты и размера сообщений. XSS предотвращается textContent для имени и текста. Это общий учебный чат: все участники видят все сообщения. Приватные сообщения и TLS в локальном варианте не заявляются.

`npm test` проверяет две связи, рассылку, идентификаторы, невозможность подменить имя отправителя, сброс typing, историю и выход. Тест проходит локально. Для проверки экранирования в браузере отправьте `<img src=x onerror=alert(1)>`: должна появиться строка, а не картинка/скрипт.

Сервер по умолчанию слушает 127.0.0.1. Для публичного размещения нужен HTTPS reverse proxy с WebSocket Upgrade и WSS, а также отдельные комнаты и авторизация для настоящей службы поддержки.

## Контрольные вопросы

1. HTTP — запрос/ответ, WebSocket — двусторонний канал. HTTP/1.1 обычно сохраняет соединение (keep-alive), поэтому утверждение «каждый HTTP-запрос всегда открывает новое соединение» из методички неточно.
2. В HTTP/1.1 handshake использует Upgrade: websocket, Connection: Upgrade, Sec-WebSocket-Key, Sec-WebSocket-Version: 13. Сервер отвечает 101 и Sec-WebSocket-Accept.
3. open — соединение готово, message — данные, error — ошибка, close — закрытие с кодом и причиной.
4. Фреймы: text, binary, continuation, close, ping, pong. Браузер позволяет отправлять text/binary и закрывать связь, но не выдаёт JS прямые ping/pong методы.
5. send отправляет данные в открытом соединении. close(1000, 'Leaving') инициирует нормальное закрытие.
6. 1000 — нормальное закрытие. 1006 — локальный признак аварийного разрыва, такой код нельзя посылать в close-фрейме.
7. input отправляет typing=true, таймер после последнего ввода отправляет false. Сервер также сбрасывает состояние через 2 секунды.
8. wss.clients хранит подключения сервера. Здесь Map хранит только вошедших участников и серверные имена. Альтернатива — комнаты/группы подключений.
9. Не вставлять недоверенное имя или сообщение в innerHTML. Использовать textContent. Проверять типы и длины на сервере.
10. WebSocket удобен для чатов и живых уведомлений. Для разовых загрузок, форм и кешируемых документов достаточно HTTP. Для потока только сервер→клиент можно рассмотреть SSE.
